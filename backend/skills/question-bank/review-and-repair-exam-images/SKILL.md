# 题库逐图核验与修正

## 适用范围

针对已有题目及对应元数据检查分类、边界、原卷身份、页码和答案对应关系。默认文字优先：完整题干、选项、子问和对应 MS 可可靠读取时，AI 逐题读文字判断分类；图形、公式或提取失真需要时再看图。保持完整顶层大题，不随意拆分子问。大片答题空白可保留。

本 skill 不包含自动续跑、下载整套题库或发布网站的授权。用户要求停止时，停止派单与修正，保存当前批次、未完成项和接手入口。

## 分类合同

- 先读取项目接手文档、最新状态与相应科目的分类 skill / taxonomy；来源定位和发布机制见 [项目操作说明](references/alevel-workflow.md)。
- 分类由 AI 理解题干与评分目标完成，不以关键词或程序规则代替。原卷文字能用于分类，不能据此宣称当前图片没有漏题或截断。
- 只有声明题图完整性已验收或批准修图时，必须查看当前图或修后图的全部像素，并对照原卷题干、图表、续页、最后子问和下一题起点。长图可分重叠切片，但不能遗漏区域。
- 对照正式评分标准逐子问判断目标，按得分贡献和主要作答链决定主分类。不要因为出现某个名词就额外贴标签，不把备选评分路线的所有概念都当作必考内容。
- 遵守科目和试卷阶段范围。分类清单遗漏或与真实题面矛盾时，核实当年官方考纲再判断；不要为通过规则检查而强贴无关分类。
- 主分类并列、旧考纲内容无对应类别、缺失材料或原卷本身删图时，保留合理分类与明确的复核原因。不能用高置信度掩盖不确定性。
- 数学独立得分并列时按科目 skill 的主要作答链/既有合理主标签规则结案，保留实质多标签；生物备选评分路线写入理由，不机械合并所有备选次标签。
- 原卷缺失时，只记为现图核验；获取有授权的公开原卷后，确认科目、年份、考季、试卷号、题号和来源身份再补充认证。不得用相似题替换或由生成式图像工具补造内容。

## 判定流程

多 agent 审核使用项目 [CLI 操作说明](../../docs/EXAM_REVIEW_CLI.md)。先 `init`，各 agent 以不同 worker 名 `claim`，每批首次 `context`，逐题 `show`；按需 `images`，再 `submit`。修图先 `crop stage` 并实际查看暂存图，主任务用 `apply --dry-run` 后串行应用正式批次。CLI 不自行调用模型 API。

已结案题的元数据整理、异常登记和用途导出使用 `catalog` 子命令，遵守[统一格式合同](../../docs/QUESTION_BANK_FORMAT.md)。分类状态和内容质量分开：缺材料、官方取消计分及答案争议可以保留质量警示，同时分类结案。正常练习和计分使用相应用途导出，不直接使用归档全集。

1. **领取与去重**：用稳定题目 ID 划分互不重叠批次。台账中同 ID 的后续复核替代旧结论，不重复累计。队列序号只用于定位，不是题号或完成数量。
2. **核验来源**：匹配 QP/MS 的封面或页眉身份；区分 PDF 物理页码与印刷页码。页码候选只是候选，须找到完整题目边界。
3. **文字优先审题**：读取完整原卷题文及对应 MS；提取不可靠或依赖图形时读取像素。若同时核验图片边界，检查图、表、选项、公式、题号、子问及续页。原卷空白页可留在图片中，但不算含题来源页。
4. **按评分点分类**：记录各子问分值、总分、候选标签和依据。分值总和必须与题面 / MS 一致；MCQ 独立求解并核官方答案，避免把干扰选项当作考点。
5. **修复并复看**：只修确认的混题、漏题、截断、重复或错页。先暂存、备份，再写回。修后逐图与原卷复看，确认最后一个得分点和必要图表都在。
6. **落盘与验收**：同步原始导出来源、正式题图、分类副本、元数据与预览，检查重建后不会恢复旧图；保留未解决项并更新接手状态。

## 输出合同

每条记录至少包含：题目 ID、当前图片路径、QP/MS 路径、核实物理页码、分类前后值、复核状态和原因；明确 `review_mode=text/image/mixed` 与独立 `crop.status`。看图记录填写实际查看的证据路径；原图和修后图完整验收另记尺寸及覆盖范围。历史队列要求的指纹按其协议保留；仅整理元数据时使用无需哈希的 `catalog` 路径。

裁切变更另存：原图与暂存图路径、前后尺寸、裁切坐标或来源页区域、备份路径、修后复看结论。页码、分类与图像修复分别记录，不能把“页码修正”混报为“重裁图片”。

进度分别报告：

- 已逐图核验的去重 ID 数，以及其中原卷缺失的数量。
- 文字分类审核数量；不得加进逐图验收数量。CLI 的工作区统计独立保存，汇总时按 ID 去重。
- 已正式应用的分类决定数（包含保留原标签和驳回候选，不等于实际改类数量）。
- 已修复图片数、来源页码 / 尺寸修正数。
- 子代理待主代理复核、已应用但未合并台账、仅部分查看的批次。

结构检查通过只说明结构与引用一致；不得据此声称全部题图或分类均正确。

## 代理分工与验收

用户要求或允许并行时，按独立 ID 批次分配子代理；模型和推理档位遵从当前用户要求。先检查当前可用并行槽位；不要把历史代理列表当作正在执行的代理，也不要无依据声称指定档位已启动。

子代理只写自己的审计分片、暂存修复和证据，主代理串行修改共享正式输出。持续执行任务时，一批完成后按最新状态接下一批；用户要求停止时不再续批。

交接保存最新可靠指针、精确 ID / 区间、已应用批次、待合并分片、未应用候选、检查结果和恢复动作。运行中的模型上下文不是持久检查点；未写入的观察应标记为未验收。

## 常见错误

| 错误 | 处理 |
| --- | --- |
| 按图片高宽、OCR 或自动规则直接宣称逐图通过 | 打开真实像素并与原卷逐题匹配 |
| MS 搜索命中“2”就当作 Q2 | 区分评分条目编号与真正的 Question 2 表头，核对完整小题与分数 |
| 修了发布图，重建又变回旧图 | 同步 manifest 的 output_file、页码、宽高和持久来源 |
| 同名题图和答案被一起覆盖 | 按资产目录角色与路径筛选，不能仅按文件名复制 |
| 因大片留白反复重裁 | 用户允许时保留，只修实质内容边界 |
| 上下文恢复后退回旧批次 | 读取最新 current_state / checkpoint，与 ledger 和正式批次交叉核实 |
| Paper 1 出现 AI 就强行归入 A Level AI | 区分当年考纲中的 AS 应用 / 影响和 A Level 技术机制，按官方条文判定 |
