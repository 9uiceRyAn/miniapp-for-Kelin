# 第一期：题库实施与验收

状态：代码已进入完整应用开发版；自动化验证与待执行项见 [验证记录](../VALIDATION.md)。样本题库服务通过后继续 Agent，正式全量题库验收待分类交付。

## 实现顺序

| 步骤 | 工作 | 完成条件 |
| --- | --- | --- |
| 1. 数据与环境 | 先冻结独立样本与媒体，提供应用侧字段验证，确认开发环境；正式全量清单稍后接入 | 有可复现导入输入、内容哈希和增量迁移方案 |
| 2. 后端接入 | 导入数据、标签与修订；实现列表/筛选/详情/媒体 API | 真实数据可查询，重复导入幂等，沿用现有鉴权 |
| 3. 原生页面 | 首页入口、列表、详情、答案材料、音频与品牌对齐 | 原生端完整浏览，不出现尚不可用的 Agent 操作 |
| 4. 独立验收 | 执行下表并回归原资料功能 | 题库可独立交付，证据齐全后进入第二期 |

题库请求不依赖模型连接；完整应用同时交付 Agent 模块，但模型故障不能阻断题库浏览。资源 ID 与修订是本期数据契约，后续引用直接复用。

## 验收矩阵

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| QB-01 | 原资料功能回归 | 登录/设备记忆/退出、A–E 分类、上传下载、ZIP 导出和 marks 正常 |
| QB-02 | 两名用户标记同一文件 | 各自状态独立，保留原 `files.id` 和关联关系 |
| QB-03 | 未配置或安装 Agent 模块 | 登录后题库查询、详情、图片和音频完整可用，无模型调用 |
| QB-04 | 学科、数据集、关键词、标签组合筛选 | 分页和数量正确，同名标签不跨 collection 错误合并 |
| QB-05 | 单题、题组、整卷、无答案条目 | 标题/范围/材料符合实际，不把所有条目当成单题或有标准答案 |
| QB-06 | question/source/answer/ms/sm/in/si 及未知 kind | 按角色展示并保留原 label，未知资源不静默丢弃 |
| QB-07 | 重复导入及内容更新 | 不重复建题，更新形成新修订，明确读取旧修订时不替换内容 |
| QB-08 | 未登录或过期身份请求 API/媒体 | 请求受保护；合法用户在真机可读取受控图片/音频 |
| QB-09 | 待审核、provisional、缺失媒体或失效修订 | 保留实际质量状态，缺失有明确提示，不伪装成已验证或最新原文 |
| QB-10 | 手机/桌面题库浏览 | 长标题、多图、来源、音频与返回导航可用，符合现有品牌 |

## 交付证据

- 数据：导入清单、内容哈希、数量核对、ID 唯一性、标签作用域和媒体检查结果。
- 后端：实际数据下的查询、修订、幂等与鉴权测试；原有文件和 marks 回归结果。
- 小程序：开发者工具编译、桌面预览、真机流程结果，注明验证环境。
- 交付：迁移执行方式、媒体存储与部署配置、回退步骤；保留生产 `.env`。

现有 `npm test` 的语法检查不能作为上述全部案例通过的依据。未完成的案例应保留待验收状态。

## 本期接入参数

- 真实服务器 Node.js/MySQL 版本、表结构、文件目录。
- 正式题库冻结版本和媒体来源。
- 小程序图片/音频的鉴权访问方式及实际设备兼容性。

平台模型、文档解析和流式会话参数留到[第二期实施与验收](../phase-2-agent/06-delivery-and-acceptance.md)确认，不阻塞本期。
