# 第二期：创建助手、Skill 与运行时

本期在[题库验收](../phase-1-question-bank/03-delivery-and-acceptance.md)通过后实现。身份、资源修订和 API 包装沿用[共用约定](../01-shared-foundation.md)；后端实体和路由见[后端与 API](04-backend-and-api.md)。

## 创建助手

教师在产品内通过对话描述目标、教学风格、评价方式和参考材料。创建助手生成的是可检查的 Skill 草稿，不直接发布或替教师执行管理员操作。

实现约定：

1. 创建助手输出名称建议、简介、教学指令、资料引用和工具使用说明。
2. Skill 以平台管理的 `SKILL.md` 内容及资源清单表达；每次应用生成结果形成不可变 SkillRevision。
3. 教师可以继续对话修改草稿、查看生成内容、选择教学模型并试聊。
4. 生成结果只更新草稿；发布由教师操作触发，已发布版本不原地修改。
5. 创建助手的系统配置由平台维护；创建助手使用的模型配置与最终教学 Agent 的模型配置分别记录。
6. 创建助手会话仅归属教师，不混入学生历史，也不自动成为公共资料；会话绑定平台创建助手的版本，目标教学 Agent 单独关联，避免混用二者的指令或模型。

本期不要求教师手工编写或上传 ZIP 才能创建 Agent。生成 Python/JavaScript、执行包内脚本、接入任意自定义工具不属于已确认范围。

## 资料与 Skill 的关系

- Skill 指令和资源清单形成版本快照。
- 教师明确提交为教学知识材料的内容进入公共资料库；资料不是只有当前 Agent 才能检索的私有知识集合。
- 上传中的文件、尚未解析成功的内容不作为成功可检索资料展示。
- Skill 内可以推荐资料、设置默认查询条件，但不能把这些推荐误实现为教师选择的工具/题库权限白名单。
- 创建助手对公共资料的检索沿用平台工具，记录生成 Skill 时实际参考的资料版本。
- 学生作业与聊天内容不因被模型读取而进入公共资料库。

## 发布与会话版本

正式发布版本包含 SkillRevision、教师选定的模型与推理参数快照。模型连接密钥使用服务器受保护的连接引用，不复制到版本文本或客户端。

| 行为 | 必须得到的结果 |
| --- | --- |
| 修改草稿 | 已发布版本、已有学生会话不变 |
| 教师试聊 | 固定启动时草稿快照；修改后另开试聊验证 |
| 发布新版本 | 新会话使用新版本；旧会话继续原版本 |
| 继续旧会话 | 使用原指令与模型配置，同时允许检索最新公共资料 |
| 轮换平台 API 密钥 | 不改变教学模型 ID、指令和推理参数快照 |
| 原模型不可用 | 明确失败原因；不静默切换到另一模型并宣称仍为原版本 |

同一账号的新会话不读取其他会话作为隐式记忆。教师查看学生记录属于业务读取权限，也不自动把学生记录注入创建助手或其他 Agent。

实现约定：常规下架从公开入口移除并阻止新会话，历史记录保留。若必须停止既有会话继续调用，应使用明确的停用状态并向用户显示原因，不通过修改旧版本内容实现。

## 上下文

每个 Run 固定：

- 触发消息的序号及之前的有效会话历史；
- AgentVersion、SkillRevision、模型 ID 与参数；
- 当前消息附件、已选题目及其明确引用版本；
- 执行中实际调用的工具版本和公共资料修订。

不得把 Run 启动后追加的消息纳入该轮输入。对历史内容按模型上下文窗口构造输入，保留必要的题目、附件引用和工具调用/结果关联。技术性的上下文、输出长度和执行时间限制不是费用额度。

文字、图片、PDF、DOCX 必须进入实际处理链路。图片走已验证的视觉输入或平台识别工具；文档提取正文、页码/段落位置，必要时识别扫描内容。失败时显示具体解析状态，不能只显示“上传成功”并让模型假定已读。

## Run 状态与事件

实现约定状态：

`queued → running → completed | failed | cancelled | interrupted`

- 先保存消息与 Run，再及时返回运行 ID；不等待整段模型回答完成才返回。
- 会话并发发送使用幂等键与活动 Run 约束。
- 取消通过服务端 Run 状态和执行信号传递，终态只完成一次。
- 服务重启后，原活动 Run 明确转为中断或按可验证规则恢复；不能永远停在“生成中”。
- 不自动重发可能已产生模型费用的整轮请求。

| 事件 | 前端用途 |
| --- | --- |
| `run-started` | 进入生成状态 |
| `text-delta` | 逐步展示回答 |
| `tool-started` | 显示实际工具名称和进度说明 |
| `tool-completed` / `tool-failed` | 展示工具结果摘要或可理解的错误 |
| `citation-added` | 关联资料版本、页码或题目来源 |
| `run-completed` / `run-failed` / `run-cancelled` / `run-interrupted` | 结束生成并保存终态 |

事件包含 `runId`、单调递增 `sequence`、类型和时间。读取必须鉴权；从某个序号恢复时不重复渲染、重复计费。

Mastra 适配器需要消费工具与文本事件，不能继续只转发 `textStream`。工具和引用事件保存可展示摘要，完整内部诊断不能直接下发学生端。

## 小程序传输

后端事件协议与传输方式分离。实现前验证微信开发者工具、桌面微信、真机以及 Nginx 下的增量传输行为。首选在同一 HTTPS API 上传输事件；不支持增量流的环境可按 sequence 轮询同一持久化事件接口。

无论使用流式传输还是轮询，都必须及时拿到 Run ID、可取消、能查看工具进度，并在离开页面后恢复最终记录。不得用“等待整个请求完成”的方式冒充流式响应。
